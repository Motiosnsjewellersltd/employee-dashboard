ASSET HANDOVER - ADMIN / HR

This feature records items issued to employees, not advance inventory/stock. No stock totals or Available-items boxes.

ADMIN/HR USAGE
Open Tools > Asset Handover. Add Handover: choose an employee, item type (Mobile / Laptop / SIM Card / Pen Drive / Other), item details, optional serial/IMEI/mobile number, date, condition, accessories and remarks. Attach an optional PDF/JPG/PNG/WEBP photo or receipt, maximum 4 MB. Employee branch, department and designation appear automatically. Existing historical handovers can be recorded with the actual past date.

View shows the current/last holder and immutable history. Transfer moves the same item record to another employee. Return Received marks it returned. Use the Returned status filter and Handover Again to issue a previously returned item. Edit Details records previous details in history; it does not change the holder. No delete operation is exposed. The same item type + normalized identifier cannot be registered a second time: open the existing record instead. Empty identifiers cannot prove whether two physical items are the same.

Filters: employee/item/serial search, branch, employee, item type and assigned/returned/all status. There are 50 rows per page. Employee details show their currently assigned items for Admin/HR only; transferred items appear under the new holder. Holder name/code/branch/department/designation are snapshots recorded at handover/transfer time, while events keep the older snapshots. Employee profile changes later do not rewrite past handover history.

PERMISSIONS
Employees and floor managers with EMPLOYEE role have no menu, profile section, API or attachment access. ADMIN can manage all handovers. Two new HR permissions appear under Permissions: Asset Handover menu visibility and Add/edit/transfer/receive handovers. Both start enabled for HR. With menu enabled and action rights blocked, HR can view history and download receipts but cannot change records. All checks are server-side as well as UI-side.

DATABASE / DEPLOYMENT
Apply this patch on the existing dashboard source with earlier approved updates, including the report viewer fix. The ZIP contains three modified existing files: DashboardApp.tsx, lib/permissions.ts and prisma/schema.prisma; the remaining feature source/setup files are new. Prior calendar/report viewer files are not replaced by this feature except their imports/usages remain in the existing DashboardApp.tsx.

The installer runs Prisma generate, TypeScript, production build and handover tests. It then applies prisma/asset-handovers.sql using the project's existing local .env database settings. It creates only AssetHandover, AssetHandoverEvent and AssetHandoverAttachment plus their indexes/foreign keys/checks, in a transaction. It is safe to rerun the setup; no db push, seed, reset, data migration or alteration/deletion of employee/attendance/leave/scheme tables is used. This is the DASHBOARD POSTGRESQL database, not the Realtime SQL Server. DIRECT_URL is preferred; if absent the setup uses DATABASE_URL for this process only. No .env file or hosting variables are changed. Do not share database credentials.

After setup the installer commits only the feature files and pushes the current branch to origin HEAD. Unrelated pre-staged files are excluded by git commit --only. No force push. If a check/setup/push fails it stops; send the exact error. If your Git branch has unmerged conflicts, resolve them before applying the patch. Once Vercel deployment completes, refresh the app.
